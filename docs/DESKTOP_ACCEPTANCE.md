## 验收发现并修正的问题

1. Desktop 1.19.5 实际使用 **Node sidecar**。原先 Bun-only SQLite/HTTP/启动 API 会让 Skill 可见而工具未注册；改为运行时选择 Node/Bun SQLite、node:http、node:child_process，并构建 JS 入口。增加了真实 Node 插件 smoke test，覆盖 SQLite CRUD、HTTP 鉴权、注入 client、一次提交及成功终态。
2. 本机原有默认模型连接返回 `ECONNRESET`，Copilot 菜单中的一个同名路由也返回 ModelNotFound。没有改写用户模型配置或凭据；新增可选的任务模型，仅为样例选择已存在且能工作的 OpenAI 路由。默认选项仍沿用宿主。
3. 成功状态的空说明原来显示「等待宿主状态更新」，已修正为宿主已确认完成。

## 飞书兼容性核查

本轮没有修改全局 opencode.json、原飞书配置、既有 loader、Desktop bundle 或 Markdown helper；验收前后私有本地完整性哈希均一致。Desktop 后端的运行标识保持相同；重建只限定临时目录。已知飞书入口以其 owner directory 为边界，新任务会话不进入该聊天映射；样例会话没有产生飞书桥日志或发送操作。没有加载第二个机器人入口。

这些证据支持「代码和配置未被破坏、任务会话不接管飞书映射」。**不等于真实飞书收发已重新验收**：没有授权向真实用户发送测试消息，因此没有执行长连接断线重连、卡片、附件或交互回调在线测试。

## 尚未执行的操作与原因

- 没有退出/杀死现用整个 Desktop 或其后端：这可能中断用户既有飞书及其他任务。现用环境验证的是**项目插件实例重建**，完整后端进程重启另由隔离测试覆盖。
- 没有修改安全设置、授予持久凭据、默认放行权限、重置工作区或发布公开仓库。
- 现用 Desktop 的逐项审批按钮、设备真实睡眠/关机、跨平台、长期运行与真实飞书在线收发仍需单独安排。

当前源码项目的本地包装器已更新；曾加载过旧版的项目仍可能持有宿主缓存。在用户方便结束其他任务时再重建该项目实例或退出重开 Desktop，不能以刷新浏览器页面代替宿主加载。
